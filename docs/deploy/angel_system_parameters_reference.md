## 阅读约定

- 本表覆盖 `AngelConf` 中 **384 个不同配置键 / 385 条键声明**，按完整键去重；重复常量保留冲突说明。
- 默认列表示源码 `DEFAULT_*` 值；若通过读取点配对会注明。**声明默认不等于启动时已写入 Configuration，也不等于最终运行值。**
- `CPU` 是当前 JVM 的 `availableProcessors()`；非固定机器核数。数值表达式按源码计算，不代入本机值。
- 空串和空白字符串区别记录；没有默认常量不等于可以不配置，也不保证消费者没有自己的 fallback。
- “无主代码引用”是本仓库 `src/main` 中静态检索结果，排除了注释和声明；不是对外部调用、动态字符串构造、插件或资源配置的不可用断言。
- 每项均可通过 XML/`Configuration.set*` 配置；Spark 使用手册的专用映射或 `spark.hadoop.<完整键>`。JVM-only、派生参数和保留字段需看专门说明。
- 保留英文源码注释摘录供交叉核对；其中历史部署范围/单位错误以中文说明与实际消费者为准。

Historical behaviour (false, the default): if the user sets angel.am.java.opts, the entire masterJVMOptions block in AngelYarnClient is skipped. The historical default required the operator to set channel.type=epoll explicitly, which most deployments forget to do and silently miss out on Epoll edge-trigger / SO_REUSEPORT / fewer syscalls (typically 15-25% lower tail latency under load).  Set to false to keep the legacy behaviour ("only honour channel.type"). Setting channel.type=nio + auto.epoll=true still upgrades to epoll on Linux. Why this exists. The per-partition retry path (transport-layer max try counter) only counts actually-sent attempts; a partition request that gets stuck in the failed-cache heap because its target PS is marked as isFailed and never re-promoted (e.g. the location-refresh chain never fires for it) increments no counter and is never failed. The aggregate user request it belongs to then waits forever, because its FutureResult is set only when all partition responses arrive or when the per-partition path gives up. We have observed Spark tasks parked on FutureResult.get() for over an hour in exactly that state. This watchdog is the only universal escape hatch.  How to size it. Should be strictly larger than the longest legitimate single user request (matrix update / PSF call) seen on the cluster, including a generous margin for retries and back-off. The default 30 minutes is intentionally conservative — we would rather leak a request for half an hour than fail a healthy but slow request mid-flight. Set lower (e.g. 5–10 minutes) on latency-sensitive online-serving deployments, or to 0 to disable entirely.
- `angel.psagent.user.request.deadline.check.interval.ms`：Period at which the adapter-level deadline watchdog scans all in-flight user requests, in milliseconds. Must be strictly less than #ANGEL_PSAGENT_USER_REQUEST_DEADLINE_MS; the actual fail-fast delay is then bounded above by deadline + period. The default 30 s is sufficient for the typical 30-minute deadline.
- `angel.psagent.master.rpc.timeout.ms`：Per-call timeout (ms) wrapping every master-RPC issued by the PS-location refresher and the heartbeat path (e.g. getPSLocation, psFailed, isPSExited, getState). Without a hard ceiling, a stuck master Netty channel can block the single PSLocRefresher thread for the OS-default TCP retransmit window — easily tens of seconds to minutes — during which no further PSes can be recovered. We instead dispatch each master RPC to hbThreadPool and time-bound the wait, so a slow master only fails THIS one refresh attempt; the next 5 s tick retries automatically.  The default 5 s is large enough to absorb normal RPC latency and an occasional GC pause on master, but small enough that a partial outage doesn't snowball into a cascading PS-loss event on the client.
- `angel.psagent.cache.sync.timeinterval.ms`：PSAgent caches synchronization time interval in milliseconds. The caches contain matrix caches and clock caches, which synchronize data from pss regularly. Matrix caches are used to cache matrix data splits. Clock caches are used to cache the clock values of all matrix partitions.
- `angel.psagent.sync.clock.enable`：Weather we need update the matrix clock and task iteration to master synchronously.

## 完整性与边界

- 枚举了所有 `public static String` 参数声明（含非 final）并求值前缀拼接；排除类型标识、固定文件名和组合字段后缀。
- `angel.ps.router.type` 存在两个声明但只计一个实际键；两套默认值的冲突已在表中显式标注。
- 消费者自定义的字符串键、Spark 专用键、JVM system property 和脚本变量见[参数手册](angel_system_parameters.md)。
- 数学内核、每个算法的 `ml.*` 超参数、每矩阵属性及完整 Hadoop/Spark 配置不在本表声称的覆盖范围；需阅读相应模块配置类和算法参数文档。
